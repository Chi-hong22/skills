科研周报生成 skill 的评测样例，用于 with-skill/baseline 对比评审。

## 文件说明

| 文件 | 功能 |
|------|------|
| `evals.json` | 测试提示集（3 个场景），可直接用于 skill-creator 评测流程 |

## 评测场景

| ID | 场景 | 关注点 |
|----|------|--------|
| 1 | 单主题混合工作 | 是否过滤低价值工作、按问题归并并提炼判断变化 |
| 2 | 多主题周报 | 概述能否快速说明主线、主题是否按研究价值排序且详略合理 |
| 3 | 含公式/图片/复杂标签 | 是否只保留支撑判断的公式与图片，并维持来源和 tags 追踪 |

## 核心检查项

所有 eval 默认都应检查以下内容：

1. 开头概述使用自然段，不使用列表，能够独立说明本周工作和课题变化。
2. 详细内容按研究问题归并为主题，不按文件、每日任务或技术名称机械拆分。
3. 低价值工作不占主体；详细内容只保留支撑判断和复盘所需的技术细节。
4. 明确区分结果、合理判断、待验证假设、暂无法解释的问题和已否定方案。
5. 下一验证由证据缺口自然推出，并说明支持或改变判断的条件。
6. 概述与详细主题不重复堆叠同一信息。
7. 若上下文可解析到历史周报，应先核对本次候选时间范围，再继续生成。

## 后续迭代流程

1. 使用 skill-creator 的测试流程，为每个 eval 同时生成 with-skill 和 baseline 运行
2. 通过 `generate_review.py` 生成评审视图，人工评审输出质量
3. 根据反馈修订 SKILL.md，重新运行测试
4. 迭代至输出稳定满意后，可选执行 description optimization
