# Evals

科研周报生成 skill 的评测样例，用于 with-skill/baseline 对比评审。

每个场景都在 prompt 中提供完成该场景所需的全部事实：范围门禁场景包含上一份周报范围和候选日期，内容生成场景包含已确认范围和候选日志正文。评测不依赖本机偶然存在的文件，也不允许模型补造缺失证据。

## 文件说明

| 文件 | 功能 |
|------|------|
| `evals.json` | 测试提示集（4 个场景），可直接用于 skill-creator 评测流程 |

## 评测场景

| ID | 场景 | 关注点 |
|----|------|--------|
| 1 | 范围确认门禁 | 未经用户确认时是否只回显候选范围而不生成周报 |
| 2 | 单主题混合工作 | 是否过滤低价值工作、按问题归并并提炼判断变化 |
| 3 | 多主题周报 | 概述能否快速说明主线、主题归并是否合理且详略得当 |
| 4 | 含公式/图片/复杂标签 | 是否只保留支撑判断的公式与图片，并维持来源和 tags 追踪 |

## 核心检查项

所有 eval 共同检查：只依据 prompt 已提供的事实，不依赖本机文件，不补造证据。

Eval 1 检查范围确认门禁：

1. 正确计算并回显候选范围、日志数量和日期。
2. 明确等待用户确认，不提前生成概述、主题正文或周报文件。

Eval 2-4 检查周报内容：

1. 开头概述使用自然段，不使用列表，能够独立说明本周工作和课题变化。
2. 详细内容按研究问题归并为主题，不按文件、每日任务或技术名称机械拆分。
3. 低价值工作不占主体；详细内容只保留支撑判断和复盘所需的技术细节。
4. 明确区分结果、合理判断、待验证假设、暂无法解释的问题和已否定方案。
5. 下一验证由证据缺口自然推出，并说明支持或改变判断的条件。
6. 概述与详细主题不重复堆叠同一信息。

## 后续迭代流程

1. 使用 skill-creator 的测试流程，为每个 eval 同时生成 with-skill 和 baseline 运行
2. 通过 `generate_review.py` 生成评审视图，人工评审输出质量
3. 根据反馈修订 SKILL.md，重新运行测试
4. 迭代至输出稳定满意后，可选执行 description optimization
