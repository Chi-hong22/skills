# Research Weekly Report Skill

<!--
一旦本文件夹有所变化，请更新本文档。
-->

将碎片化日报筛选并归并为兼顾导师速读与个人复盘的科研周报。
当前版本强调三件事：

1. 先自动判定上一份周报的实际覆盖边界，再圈定本次候选日志范围并与用户核对。
2. 开头使用自然段概述本周工作、课题变化和关键问题，让导师快速理解主线。
3. 后文按研究主题保留进展、判断、问题、下一验证及必要技术细节，服务长期复盘。

核心流程：历史周报定位 → 覆盖范围解析 → 用户核对 → 重要性过滤 → 研究问题归并 → 自然段概述 → 主题详述 → 周报输出。

## 工作流升级点

### 1. 自动检查上一份周报覆盖时间

生成本次周报前，优先定位最近一份历史周报，并以正文中的 `时间范围` 结束日期作为边界基准，而不是只看文件名。

### 2. 自动圈定本次候选日志范围

默认规则：

1. 若成功解析上一份周报，则本次开始日期 = 上次结束日期 + 1 天。
2. 本次结束日期 = 当前输入日志中最近一篇日志的日期。
3. 只将落在该范围内的日志视为候选日志。

### 3. 与用户交互核对

自动判定后，不直接生成周报，而是先向用户回显以下信息并请求确认：

1. 上一份周报路径或标题。
2. 上一份周报的时间范围。
3. 本次候选时间范围。
4. 本次纳入的候选日志日期列表或数量。
5. 是否需要排除补记日志、无关记录、非周报材料。

### 4. 重要性过滤与问题归并

周报不覆盖全部日报，只保留改变结果、问题、判断或方向的内容。文献、实验、代码、写作和讨论若服务同一研究问题，应归并为一个主题，而不是按动作分别列出。

### 5. 前短后详

- `本周概述`：1-3 个连续自然段，不使用分点，只呈现本周最重要的工作与变化。
- `主题详述`：每个主题最多使用“进展与判断、当前问题、下一验证”三层，保留必要证据和技术细节。

## 时间范围判定规则

1. 优先读取最近一份历史周报正文中的 `**时间范围**：YYYY-MM-DD 至 YYYY-MM-DD`。
2. 若历史周报存在但缺少标准时间范围，应明确告知用户“无法自动解析上一份周报覆盖边界”，不要臆造。
3. 若不存在历史周报，则退回到当前输入日志的最小日期和最大日期。
4. 日志日期不连续时，不补齐缺失日期，只基于真实存在的日志生成候选范围。
5. 若候选范围内混入补记旧日志，必须由用户确认是否纳入本次周报。

## 内容与逻辑要求

本 skill 面向基础研究与方法研究场景，优先说明课题和判断发生了什么变化，再说明做了哪些实现动作。

每个主题重点沉淀：

1. 实质进展：课题真正往前走了什么，包括已得到的结果及其证据。
2. 判断变化：原来如何理解，新证据如何形成当前合理判断或否定原有方案。
3. 当前问题：仍在验证的假设、暂无法解释的问题、成立条件或证据缺口。
4. 下一验证：最值得获得什么证据，什么结果会支持或改变判断。
