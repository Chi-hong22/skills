# Research Weekly Report Skill

<!--
一旦本文件夹有所变化，请更新本文档。
-->

将碎片化日报转换为结构化科研周报，面向导师汇报场景。
当前版本强调两件事：

1. 先自动判定上一份周报的实际覆盖边界，再圈定本次候选日志范围并与用户核对。
2. 周报内容不仅汇总“做了什么”，还要交代研究系统、问题提出、核心思考、解决方案与当前证据。

核心流程：历史周报定位 → 上次覆盖范围解析 → 本次候选日志筛选 → 用户核对 → 研究系统梳理 → 板块填充 → 公式与图片格式化 → 周报输出。

## 工作流升级点

### 1. 自动检查上一份周报覆盖时间

生成本次周报前，优先定位最近一份历史周报，并以正文中的 `时间范围` 结束日期作为边界基准，而不是只看文件名。

### 2. 自动圈定本次候选日志范围

默认规则：

1. 若成功解析上一份周报，则本次开始日期 = 上次结束日期 + 1 天。
2. 本次结束日期 = 当前输入日志中最近一篇日志的日期。
3. 只将落在该范围内的日志视为候选日志。

### 3. 与用户交互核对

自动判定后，不直接生成周报，而是先向用户回显以下信息并请求确认：

1. 上一份周报路径或标题。
2. 上一份周报的时间范围。
3. 本次候选时间范围。
4. 本次纳入的候选日志日期列表或数量。
5. 是否需要排除补记日志、无关记录、非周报材料。

### 4. 强化研究型叙事

每个项目不能只罗列任务清单，必须补清以下信息：

1. `研究系统定位`：该项目在整体研究链路中的位置，上游和下游关系是什么。
2. `问题提出`：本周聚焦的问题为何成立，为什么值得研究。
3. `核心思考`：当前的判断、机理分析、假设、方案取舍依据是什么。
4. `解决方案`：本周实际采用或计划采用的技术路线、模型、实验方案是什么。
5. `当前证据`：已有实验结果、观察现象、阶段性结论、局限与下一步是什么。

## 时间范围判定规则

1. 优先读取最近一份历史周报正文中的 `**时间范围**：YYYY-MM-DD 至 YYYY-MM-DD`。
2. 若历史周报存在但缺少标准时间范围，应明确告知用户“无法自动解析上一份周报覆盖边界”，不要臆造。
3. 若不存在历史周报，则退回到当前输入日志的最小日期和最大日期。
4. 日志日期不连续时，不补齐缺失日期，只基于真实存在的日志生成候选范围。
5. 若候选范围内混入补记旧日志，必须由用户确认是否纳入本次周报。

## 研究型叙事要求

本 skill 面向基础研究与方法研究场景，写作时应优先说明“为什么这个问题成立”与“当前如何理解这个问题”，再写“做了哪些实现动作”。

推荐叙事顺序：

1. 研究系统背景：交代项目在整体课题中的位置。
2. 问题提出：指出当前科学问题、机制难点或工程瓶颈。
3. 思考分析：说明目前的分析框架、假设、判断依据。
4. 解决方案：给出技术路线、模型设计、实验设计或迭代路径。
5. 当前结果：记录证据、观察、指标、局限与下周推进方向。
