# Research Weekly Report

## 何时使用

当满足以下任一条件时触发本 skill：

- 用户明确要求生成科研周报
- 用户提供了一批日报并要求汇总、整理、归纳
- 用户提到"导师汇报""本周进展""写周报"等场景
- 用户在 Obsidian 笔记环境中要求从日志生成周报

## 输入要求

执行前需确认以下信息已到位，缺失时主动向用户索取：

| 必需项 | 说明 |
|--------|------|
| **日报内容** | 至少 1 篇，含 frontmatter tags 和正文中的【日期·分类】标注 |
| **候选日志来源** | 当前用于生成周报的日报文件、文件夹或日志集合 |

| 可选项 | 说明 |
|--------|------|
| **图片文件** | 日报中引用的截图、训练曲线等，用于生成准确描述和附图索引 |
| **历史周报路径/周报根目录** | 用于自动定位上一份周报并解析其覆盖时间；未提供时优先从目标输出目录附近推断 |
| **输出路径** | 默认 `/04_自我管理/00_日志/{YYYY}/{MM}/周报_{YYMMDD}.md`，用户可自定义 |

## 核心规则

这些规则约束整个生成过程，不可违背：

| 规则 | 说明 |
|------|------|
| **时间范围判定** | 优先读取最近一份历史周报正文中的 `时间范围`；本次开始日期 = 上次结束日期 + 1 天；本次结束日期 = 当前输入日志中的最近日期 |
| **用户核对** | 自动得到候选范围后，必须先回显上一份周报范围、本次候选范围、候选日志列表/数量，并与用户确认后再生成 |
| **研究叙事** | 每个项目必须明确交代 `研究系统定位`、`问题提出`、`核心思考`、`解决方案`、`当前证据/局限/下一步`，禁止退化为流水账 |
| **Tags** | 保留 `日志/周报`；过滤其他 `日志/` 前缀；提取非日志类 tags |
| **时间格式** | `YYYY-MM-Do HH:mm:ss dddd`（如 `2026-01-22nd 10:36:16 Thursday`） |
| **图片处理** | 正文用"见图X"引用，附图索引插入 `![[image.png]]` |
| **公式格式** | 行内 `$...$`，独立 `$$...$$` |
| **来源追踪** | 关键信息后标注【YYMMDD·分类】，如 `【260113·实验测试】`，使用 6 位缩写日期 |
| **语气风格** | 学术报告式 + 克制反思（"进一步意识到..."） |
| **板块选择** | 只含有实际内容的板块，禁止"待补充"占位；省略板块时保留原始 1-9 编号，不重新编排 |
| **事实导向** | 仅使用日报内容，不联网补充，不臆造数据 |

## 执行流程

```text
1. 定位历史周报 → 优先寻找最近一份周报并解析其 `时间范围`
2. 生成候选范围 → 以上次结束日期次日为开始，以当前输入日志最新日期为结束
3. 用户核对   → 回显上次范围、本次候选范围、候选日志列表/数量，请用户确认或修正
4. 读取日报   → 提取 tags、日期、分类，并按项目或专题聚类
5. 读取图片   → 理解内容，生成准确描述（无图片则跳过）
6. 填充板块   → 先写研究系统定位/问题提出/核心思考，再按项目组织9大板块
7. 格式化     → LaTeX 公式、来源标注、图片索引
8. 输出       → 保存到目标路径
```

### 板块映射（日报分类 → 周报板块）

| 日报分类 | 周报板块 |
|----------|----------|
| 代码编写 | 技术路线、核心模型、解决思路 |
| 实验测试 | 研究方法、仿真结果、存在问题 |
| 文献阅读 | 问题提出、核心思考、难点背景 |
| 论文撰写 | 小论文撰写任务 |
| 学术交流 | 研究系统定位、方向调整、问题提出 |
| 灵感思考 | 核心思考、难点突破、解决思路 |

### 时间范围判定规则

执行时遵循以下优先级：

1. 优先解析最近一份历史周报正文中的 `**时间范围**：YYYY-MM-DD 至 YYYY-MM-DD`。
2. 成功解析时，本次候选开始日期 = 上次结束日期 + 1 天。
3. 本次候选结束日期 = 当前输入日志中的最近日期，而不是今天日期。
4. 若没有历史周报，则退回到当前输入日志的最小日期和最大日期。
5. 若历史周报存在但时间范围格式不标准，必须明确告知用户无法自动解析，不得猜测。
6. 若候选范围内存在补记旧日志或明显无关日志，必须在生成前向用户询问是否排除。

### 用户核对口径

正式生成周报前，必须至少向用户确认以下内容：

1. 上一份周报标题或路径。
2. 上一份周报的时间范围。
3. 本次候选时间范围。
4. 本次纳入的候选日志数量，必要时附日期列表。
5. 是否需要排除补记、无关记录、未完成材料。

### 研究型叙事骨架

每个项目先写三条高密度信息，再进入 9 大板块：

1. `研究系统定位`：说明该项目位于整体课题中的哪一层，服务哪个核心目标。
2. `问题提出`：说明本周聚焦的科学问题、机制问题或工程问题，以及提出原因。
3. `核心思考`：说明当前判断、机理分析、假设、方案取舍依据。

基础研究场景下，应优先交代“问题为什么成立”“当前如何理解这个问题”“为什么选择当前方案”，再写工程实现细节。

### 多项目场景

当日报涉及多个项目时，为每个项目创建独立的 `## 项目N：{项目名称}` 章节，各自包含适用的板块子集。项目排序按重要程度或工作量降序。

### 图片场景

收到图片时：先理解图片内容（训练曲线、架构图、截图等），在正文对应位置用"见图X"引用，最后在附图索引中插入 `![[attachments/image.png|描述]]` 并附带准确的文字描述。

## 输出契约（不可变）

### Frontmatter

```yaml
---
标题: 周报_YYMMDD
tags:
  - 日志/周报
  - [从日报提取的非日志类 tags]
创建时间: YYYY-MM-Do HH:mm:ss dddd
编辑时间: YYYY-MM-Do HH:mm:ss dddd
---
```

### 正文结构

```markdown
<!-- markdownlint-disable MD024 -->

# 周报_YYMMDD

**时间范围**：YYYY-MM-DD 至 YYYY-MM-DD
**关键进展摘要**：

- {摘要点1，体现本周核心突破}
- {摘要点2，体现思考与进步}

---

## 项目一：{项目名称}

**研究系统定位**：{说明该项目在整体研究系统中的位置、上游与下游关系}
**问题提出**：{说明本周聚焦的问题是什么、为什么提出} 【YYMMDD·分类】
**核心思考**：{说明当前判断、机理分析、假设或方案取舍依据} 【YYMMDD·分类】

### 1. 研究内容标题
{一句话概括}

### 2. 研究方法
- {算法/策略/实验设置，以及与问题提出的对应关系} 【YYMMDD·分类】

### 3. 技术路线
- {实现步骤} 【YYMMDD·分类】

### 4. 核心模型
- **模型架构**：{名称}
- **关键改动**：{修改点或关键假设} 【YYMMDD·分类】

### 5. 仿真结果
- **核心指标/现象**：{数值或观察结论} 【YYMMDD·分类】
- 训练曲线见图1

### 6. 存在问题
- {工程/实验问题或当前局限} 【YYMMDD·分类】

### 7. 难点问题
- {理论/机制难点，以及为何尚未解决} 【YYMMDD·分类】

### 8. 解决思路
- {已尝试方案、下一步方案与选择依据} 【YYMMDD·分类】

### 9. 小论文撰写任务
- **本周进度**：{完成内容} 【YYMMDD·分类】
- **下周计划**：{写作目标}

---

## 附图索引

- **图1**：{描述} 【YYMMDD·分类】

![[attachments/image.png|描述]]
```

每个项目只包含有实际内容的板块——如果某个板块在该项目的日报中没有对应素材，直接省略，不要用"待补充"或空占位。省略时保持原始编号（例如只有板块 1、2、5、8，则标题分别为 `### 1.`、`### 2.`、`### 5.`、`### 8.`），这样读者始终能通过编号定位到对应板块含义。
